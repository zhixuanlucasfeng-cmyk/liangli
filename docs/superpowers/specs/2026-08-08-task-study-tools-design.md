# 任务时间与 Anki 式学习助手设计

日期：2026-08-08  
状态：已批准，待实现计划  
依赖：`2026-08-07-companion-rollover-community-design.md` 中的 Supabase 账号架构

## 1. 目标

把“添加任务”从只记录名称和精力，扩展为可选的学习工作流：用户可以填写开始/结束时间，选择番茄钟、Flashcards、自测或分步清单。Flashcards 采用 Anki 式四档评价和间隔复习，卡片与复习进度在登录后跨设备同步，同时保留离线副本和本地导入导出。

## 2. 产品原则

- 时间和助手全部可选，快速添加任务仍然只需要任务名称。
- 时间提醒温和、不阻断；超时不是失败，不使用惩罚性红色或连续打卡。
- 任务、时间、精力和私人分步清单继续只存在设备本地。
- 只有用户明确创建的 Flashcard 卡组、卡片和复习进度进入账号同步。
- 未登录时 Flashcards 仍可完全离线使用；登录后由用户主动选择同步本地卡组。

## 3. 添加任务流程

### 3.1 两步式编辑器

今日页保留任务名称与精力快捷选择。点击“更多安排”展开第二步：

- 开始时间，可空；
- 结束时间，可空；
- 学习助手：无、番茄钟、Flashcards、自测模式、分步清单；
- 对应助手的最少配置。

折叠状态记住用户上次选择，但新任务不会继承上一个任务的具体时间或卡组，避免误操作。

### 3.2 时间约束

- 允许只填开始或只填结束；
- 两者都填时，结束时间必须晚于开始时间；
- 时间属于任务的 `dayKey` 所在本地日期；
- 跨午夜任务不在第一版支持，用户需要拆成两个任务；
- 换日迁移到成长池时，清除过期开始/结束时间，保留原时间在迁移来源说明中。

### 3.3 任务数据扩展

```js
{
  id: number,
  name: string,
  energy: number,
  done: boolean,
  dayKey: string,
  startTime: string | null,   // HH:mm
  endTime: string | null,     // HH:mm
  helper: 'none' | 'pomodoro' | 'flashcards' | 'quiz' | 'checklist',
  helperRef: string | null,   // 本地卡组/自测/清单 ID
  pomodoroCount: number
}
```

读取旧任务时补齐缺失字段；不重写旧 ID，不删除未知字段。

## 4. 学习助手

### 4.1 番茄钟

从任务打开番茄钟时记录 `activeTaskId`。完成一个番茄后，同时增加全局统计与该任务的 `pomodoroCount`。重置或退出不会把未完成计时算入统计。

### 4.2 Flashcards

任务可以关联一个已有卡组，或在添加任务时创建空卡组。打开任务直接进入该卡组“今日到期”队列。

复习交互：

1. 显示正面；
2. 用户点击或按空格翻到背面；
3. 显示“忘记 / 困难 / 记得 / 简单”四个按钮；
4. 每个按钮显示预计下次复习时间；
5. 选择后立即保存复习记录并进入下一张。

官方 Anki 语义保持一致：“忘记”表示未能回忆；“困难”仍然是通过；“记得”是主要的正常评价；“简单”表示几乎不费力。

### 4.3 自测模式

用户手动创建问题与答案列表。复习时随机显示问题，翻开答案后只记录“答对/答错”；第一版不调用 AI，不上传自测内容，不参与 Flashcard 云同步。

### 4.4 分步清单

每个任务拥有独立的本地步骤数组。步骤完成不增加额外精力值；任务完成时保留步骤状态，便于本地历史回看。

## 5. 间隔复习算法

第一版使用可解释的 Anki 式简化排程，不声称与 Anki FSRS 数学实现完全相同。

### 5.1 卡片状态

```js
{
  dueAt: string,             // ISO timestamp
  intervalDays: number,
  repetitions: number,
  lapses: number,
  difficulty: number,        // 1..10
  lastReviewedAt: string | null
}
```

### 5.2 四档结果

- 忘记：`repetitions=0`、`lapses+1`，约 10 分钟后再次出现；下一次成功后从 1 天开始。
- 困难：通过但缩短增长，间隔至少 1 天，约为旧间隔的 1.2 倍。
- 记得：正常增长，新卡 1 天，之后约为旧间隔的 2.5 倍。
- 简单：新卡 4 天，之后约为旧间隔的 4 倍。

间隔取整并加入稳定的卡片级轻微偏移，避免同一批卡永久聚集在同一天。最大间隔为 36500 天。所有计算写成纯函数并有固定时间输入的自动化测试。

### 5.3 每日队列

- 到期复习优先于新卡；
- 默认每天最多 20 张新卡，用户可以按卡组修改；
- 不限制到期复习数量，但只显示当前数量，不使用催促或羞耻文案；
- 当天没有卡片时显示“今天先到这里”。

## 6. 本地存储、导入与导出

Flashcards 使用 IndexedDB 保存卡组、卡片、排程状态、复习日志和待同步操作。任务仍使用现有 `DB`/localStorage。

支持：

- 导出单个或全部卡组为版本化 JSON，包含排程和复习记录；
- 导出卡片正反面为 UTF-8 CSV，不包含排程历史；
- 导入本应用 JSON；
- 导入两列 CSV（第一列正面、第二列背面）；
- 导入前显示卡片数量和冲突处理，不静默覆盖现有卡片。

第一版不直接导入 `.apkg`，因为 Anki 包格式包含 SQLite 与媒体清单，需单独设计和测试。

## 7. Supabase 同步

### 7.1 云端数据

- `flashcard_decks`
- `flashcards`
- `flashcard_reviews`
- `flashcard_sync_ops` 不上云，只保存在本地作为发送队列

每行包含 `user_id`、稳定 UUID、`created_at`、`updated_at` 和软删除时间。所有表开启 RLS，只有当前登录用户可以读写自己的卡组。

### 7.2 离线优先

每次修改先写 IndexedDB，再加入本地同步队列，界面立即更新。联网且登录时批量发送；成功后删除队列项。退出账号不会删除本地卡组，用户可以选择“仅退出”或“退出并移除此设备的云端副本”。

### 7.3 冲突策略

- 卡组名称、卡片内容：较新的 `updated_at` 获胜；
- 排程状态：较新的 `lastReviewedAt` 获胜；
- 复习日志：按稳定 UUID 合并，永不覆盖；
- 删除：软删除时间晚于内容更新时间时生效；
- 本地未同步编辑不会被较旧云端值覆盖。

设备时钟只用于展示；云端 `updated_at` 由数据库写入。离线操作使用本地序号保持顺序，上传后以服务器时间确认。

## 8. UI 与导航

现有五个主页面保持不变。“今日”任务卡增加时间与助手标签。Flashcards 从任务卡按钮和社区层“我的学习”入口进入；未登录时显示“仅此设备”，登录后显示同步状态。

Flashcard 复习界面采用漫画分镜，但卡面不旋转，保持长文本可读。键盘支持：空格翻面，1–4 选择四档。所有按钮有文字，不只依赖颜色。

## 9. 提醒

第一版只在 App 打开或恢复时显示到期/开始时间提示。若浏览器已经获得通知权限，可以发送本地通知；绝不在没有用户操作时主动申请通知权限。

不会因为任务超时自动标记失败。结束时间经过后提供“继续、改时间、放回成长池”三个选择。

## 10. 错误与隐私处理

- Supabase 未配置或断网：Flashcards 保持本地可用，显示“等待同步”。
- 未登录：不上传，导入导出照常可用。
- 同步失败：保留队列和用户输入，指数退避重试，不显示原始服务错误。
- CSV 格式错误：指出行号，不导入半份卡组。
- 云端权限拒绝：停止同步并要求重新登录，不回退到不安全权限。
- Service Worker 不缓存 Supabase API 响应。

## 11. 测试与验收

- 旧任务迁移后仍能显示和完成；新时间字段校验正确。
- 五种助手均可创建、打开、删除，旧任务默认 `helper:'none'`。
- 固定时间下四档排程输出可重复，忘记/困难/记得/简单顺序合理。
- 到期卡优先、新卡上限、跨本地午夜队列正确。
- IndexedDB 在刷新、离线和 PWA 重启后保留数据。
- JSON/CSV 导出可重新导入；冲突不会静默覆盖。
- 两个设备模拟离线编辑后能按规则收敛；第三个账号无法读取数据。
- 中英文 I18N key 一一对应，375/390/440px 无横向溢出。
- 原有任务、负荷、番茄钟、五页导航和 Service Worker 测试全部继续通过。

## 12. 非目标

- 第一版不实现完整 FSRS 参数优化；
- 不导入 Anki `.apkg`；
- 不用 AI 自动生成卡片；
- 不同步任务、心情、目标或私人清单；
- 不做班级共享卡组、排行榜或学习连续天数；
- 不因任务时间自动阻止用户操作。

## 13. 自检记录

- 文档明确区分本地任务数据与账号同步的 Flashcard 数据。
- “Anki 式”限定为交互与简化间隔复习，没有声称复刻 FSRS。
- 离线写入、同步队列、冲突和退出账号后的本地数据行为均有确定规则。
- 时间、换日和时区逻辑与已批准的本地日历日设计一致。
- 第一版范围排除了 AI 生成、`.apkg`、共享卡组和完整 FSRS，避免把任务扩展成不可验收的大系统。
