# Delta 猫伙伴 + 视觉改版 设计文档

日期：2026-08-04
状态：已批准，待写实现计划

## 背景 / 问题

`量力 Liangli` 现在的视觉是深色卡片 + 蓝紫渐变，工整但通用，没有个性、没有记忆点。开发者希望引入一只会随「今日精力负荷」变化表情的猫伙伴（工作代号 Delta），并以它为核心重新定义整个 App 的视觉基调。

约束（继承自项目 CLAUDE.md）：
- 单文件架构，一切改动都在 `index.html` 里，不引入图片资源、不引入构建工具/框架
- 中英双语字符必须一一对应（这次改动不涉及新文案，可跳过）
- 超载「提醒但不阻止」、不制造焦虑——猫的「精疲力尽」状态是「休息感」而不是「痛苦/被批评感」
- 改了 `index.html` 要把 `sw.js` 的 `VERSION` +1

## 目标

1. 用一只 SVG/CSS 手绘的 Q 版猫，把「今日」页的精力负荷从纯数字/进度条，变成一个有情绪反馈的角色
2. 把整个 App 的配色从冷色（蓝紫）换成暖色（珊瑚橙/杏色 + 猫的奶油白花纹色），让猫和界面是同一套视觉语言，而不是贴上去的贴纸
3. 不改变现有五个 tab 的信息架构和交互逻辑，只做视觉层的替换

## 非目标（这次明确不做）

- 点击猫触发彩蛋/互动动画
- 猫说话、猫的文案气泡
- 猫的成长/等级/换装系统
- 布局结构大改（导航方式、卡片信息层级保持不变）

这些留到「下一步建议」里，等这次的核心机制（状态反映负荷）验证过好不好看、好不好用之后再考虑。

## 设计

### 1. 配色基调

深色底保留（晚上用眼舒服，学生场景），但强调色系统性替换：

- 强调色：蓝紫渐变（`--accent:#4f8cff` / `--accent2:#7c5cff`）→ 珊瑚橙/杏色系
- 猫本体配色：奶油白 + 橘白花纹，作为新增的调色板变量
- 卡片圆角、阴影：略微加大/加柔，配合猫的圆润造型
- 语义色（`--ok`/`--warn`/`--danger`）保留现有绿/黄/红，不改——这套颜色已经承担「一眼看懂状态」的功能，猫的表情是叠加的第二层反馈，不是替代

具体色值在实现阶段确定，这里先定方向；改完后过一遍现有五个 tab，确认视觉语言统一（卡片背景、按钮、输入框都要跟着换）。

### 2. Delta 状态机

复用 `renderLoad()` 里已经计算好的负荷比例，不新增任何数据字段。四态：

| 条件 | 状态名 | 神态 | 对应现有语义色 |
|---|---|---|---|
| `used === 0` | idle（待机） | 眯眼趴着，尾巴轻摇，呼吸循环动画 | 无任务时的中性态 |
| `0 < used ≤ max*0.8` | content（元气） | 坐姿，眼睛睁开，耳朵竖起 | `--ok` |
| `max*0.8 < used ≤ max` | tired（有点累） | 耳朵微垂，喘气感 | `--warn` |
| `used > max` | exhausted（精疲力尽） | 趴平，闭眼，「休息感」而非「痛苦感」——不做皱眉/哭脸等负面情绪表达 | `--danger` |

四态用同一个 SVG 容器画出四组 path/元素，通过给外层容器切 class（`.delta.idle` / `.delta.content` / `.delta.tired` / `.delta.exhausted`）控制显隐，用 opacity 交叉淡入淡出切换（沿用现有 `.gauge>span` 的 transition 手法，如 `transition:opacity .4s`）。idle 态叠加一个轻微呼吸/眨眼的 CSS `@keyframes` 循环，避免看起来像静态贴图。

### 3. 布局

「今日」页第一张卡片重构：

```
┌─────────────────┐
│   🐱 (大，会变表情)  │  ← 新增，约 140-160px 高
│                  │
│ 今日精力负荷 32/100  │  ← 原有数字/进度条下移
│ ▓▓▓▓▓░░░░░░░░░   │
└─────────────────┘
```

其余四个 tab（成长池/目标/专注/记录）不动布局，只跟着换配色变量。

### 4. 实现方式

- 纯 SVG + CSS，写进现有 `index.html` 的 `<style>` 和 `<body>`，不新增文件、不引入构建工具
- `renderLoad()` 里新增：根据 `used`/`max` 算出 state 字符串，给猫的容器元素 `classList` 切一个 class；表情切换和动画完全交给 CSS，JS 不碰画法
- 不新增 `localStorage`/`DB` 字段——猫的状态永远是 `S.tasks`/`S.loadMax` 的纯派生值，刷新页面自动重新计算，天然正确，不存在状态不同步的问题
- 不涉及 i18n（猫没有文案），`I18N` 对象无需改动

### 5. 验证方式

单文件纯前端项目，没有自动化测试基础设施，手动验证：

1. `python3 -m http.server 8000` 本地起服务，浏览器打开
2. 空任务列表 → 确认猫是 idle 态，呼吸动画在跑
3. 依次加任务把负荷推过 80%、100% 两条线 → 确认猫在 content → tired → exhausted 之间正确切换，且切换是淡入淡出而不是跳变
4. 切换中英文（右上角按钮）→ 确认猫不受影响（无文案依赖）
5. 过一遍全部五个 tab → 确认配色统一，没有遗留的旧蓝紫色
6. 完成后把 `sw.js` 的 `VERSION` 常量 +1

## 风险 / 待确认

- SVG 手绘的猫是否「好看」是主观判断，无法在写代码前完全验证——先做出一版让开发者在浏览器里实际看效果，如果观感不理想，下一轮再迭代画法（这也是选择「先做出核心机制」而不是「一次性画到完美」的原因之一）
