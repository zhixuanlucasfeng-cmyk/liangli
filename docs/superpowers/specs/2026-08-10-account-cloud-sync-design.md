# 量力账号与云同步设计

## 目标

为量力增加可跳过的账号系统，让用户在 iPhone、电脑和其他设备之间同步核心成长数据，同时继续保持离线优先，并默认不上传营养、钱包与消费等敏感数据。

## 产品原则

- 未登录用户仍可完整使用本机功能。
- 首次打开可跳过账号引导；顶部头像入口可随时注册或登录。
- 登录使用 Supabase 邮箱与密码，包含邮箱验证、会话刷新、退出和找回密码。
- 云同步不能阻塞本地写入；断网时先保存本机，联网后自动同步。
- 默认不上传营养、钱包和消费记录。未来只通过独立且默认关闭的授权开关启用这些模块的同步。

## 同步范围

默认同步：

- 今日任务与任务排程
- 成长池
- 长期目标
- 专注记录与统计原始记录
- 心情记录
- Flashcards（沿用现有 IndexedDB、同步队列和合并规则）

默认仅本机：

- 热量目标、饮食记录和收藏食物
- 预算周期、储蓄建议、消费记录
- 本地恢复备份

## 账号体验

首次打开显示简短欢迎页，提供“继续使用本机”和“注册/登录”。跳过后不重复强制拦截。页面顶部显示头像入口；登录后显示账号邮箱和同步状态。

账号状态包括：仅此设备、等待网络、同步中、已同步、同步失败和需要重新登录。账号操作和同步状态均提供中英双语、可感知的文本反馈。

## 首次登录与本机数据

登录后先读取云端同步数据：

- 云端已有数据：应用先生成一份本机恢复备份，再用云端数据覆盖本机的同步模块。
- 云端为空：显示“上传这台设备的数据”与“从空账号开始”。
- 选择“从空账号开始”前再次确认；无论选择哪项，恢复备份都保留在本机。
- 营养和钱包不参与覆盖、上传或恢复选择。

本机恢复备份使用版本化 JSON，包含被云端覆盖的同步模块，不包含密码、访问令牌或 Supabase 密钥。恢复是显式操作，导入前严格验证并显示摘要。

## 数据模型

Supabase 使用归一化分表，每张表都有 `user_id`、稳定 UUID、`created_at`、`updated_at`，可删除实体使用 `deleted_at` 软删除：

- `liangli_tasks`
- `liangli_growth_items`
- `liangli_goals`
- `liangli_focus_sessions`
- `liangli_mood_entries`
- 现有 `flashcard_decks`、`flashcards`、`flashcard_reviews`

任务关联目标或 Flashcard 时只保存稳定 ID。统计视图由原始专注记录计算，不单独同步易冲突的聚合结果。

## 同步与冲突

所有本地修改先原子写入本机，再进入待同步队列。联网、重新获得焦点、登录成功或用户点击“立即同步”时触发同步。

- 任务、成长池和目标按 `updated_at` 的新版本获胜。
- 删除使用 tombstone/`deleted_at`，避免旧设备恢复已删除内容。
- 专注和心情记录按唯一 ID 做集合合并；同一 ID 冲突时仍按更新时间处理。
- Flashcards 延用现有内容更新时间、复习时间与不可变复习记录规则。
- 同步必须按当前账号 generation 隔离；切换或退出账号后，旧请求不得写入新账号或本机作用域。

## 安全与隐私

- 客户端只配置 Supabase 项目 URL 和 anon public key，绝不包含 service-role 或管理密钥。
- 所有同步表启用 RLS；读写条件必须绑定 `auth.uid() = user_id`。
- 外键引用同时验证记录属于当前账号。
- 密码直接发送到 Supabase Auth，不进入业务表、本地备份、日志或遥测。
- Service Worker 不缓存 Supabase Auth 或 REST 响应。
- 两账号 SQL 测试必须证明用户互相不可见、不可修改或删除对方数据。
- 同步 allowlist 明确列出可上传表；Life 数据不得进入序列化、队列或 REST 客户端。

## iPhone 与发布

生产版部署到 GitHub Pages HTTPS 地址。用户用 iPhone Safari 打开站点，通过“分享 → 添加到主屏幕”安装为 Web App。manifest、图标、主题色和 Service Worker 保持可安装；每次发布升级 shell cache 版本。

离线时核心功能继续工作；恢复网络后自动同步。账号 API 响应不进入离线缓存，静态资源和媒体继续按现有 PWA 策略缓存。

## 错误处理

- 登录失败不改变当前本机数据。
- 首次覆盖只有在云端数据完整验证、恢复备份成功后才提交。
- 云端响应部分失败时保留本机同步队列，不标记为成功。
- 本机存储失败时不发起云端写入。
- 会话失效先尝试单飞刷新；刷新失败转为“需要重新登录”，不删除本机副本。
- 发现不兼容或损坏的云端数据时停止覆盖，保留原本机数据并显示恢复建议。

## 测试与验收

- Auth：注册、邮箱验证提示、登录、刷新、退出、找回密码和账号切换竞态。
- RLS：两个账号不能读取、插入、更新或删除对方数据。
- 首次登录：云端有数据覆盖；云端空时两个选择；覆盖前备份；取消不改变数据。
- 离线：本机写入成功、队列保留、恢复网络后同步。
- 冲突：更新时间胜出、软删除传播、专注/心情集合合并、旧请求隔离。
- 隐私：营养和钱包永远不进入默认同步请求或备份。
- 回归：现有 66 个 Python 测试、11 个 Node 行为套件、媒体、语法和 i18n 校验继续通过。
- PWA：GitHub Pages HTTPS、iPhone 添加到主屏幕、离线启动、升级缓存和重新联网同步。

## 非目标

- 本轮不建设校园墙、聊天、关注、内容审核或公开用户资料。
- 本轮不默认同步营养与钱包。
- 本轮不迁移到 MongoDB，也不自建认证服务器。
