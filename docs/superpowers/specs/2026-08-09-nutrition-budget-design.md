# 饮食时间线与零花钱预算设计

日期：2026-08-09

## 目标

在「量力 Liangli」现有本地优先 PWA 中增加两个生活管理工具：饮食时间线和零花钱预算。功能保持温和、不说教，不根据用户体重提供医疗或减肥建议，也不强制锁定建议储蓄。

## 信息架构

底部导航继续保持五个入口。原「记录」入口改为「生活」，进入后用三个漫画标签切换：

1. 饮食
2. 钱包
3. 记录

饮食和钱包是各自独立的完整页面；现有心情记录移入「记录」标签，数据结构和历史内容不变。三个页面沿用漫画分镜、手写字和不规则卡片布局。

## 饮食页面

### 每日目标

用户自行填写每日可摄入热量。产品不根据年龄、体重或目标推导推荐值，只说明该数值由用户自行设定。

页面顶部显示：

- 今日已吃
- 每日目标
- 剩余热量

剩余热量可以是负数。超出时使用温和的行内提示，不弹窗、不羞辱用户。

### 饮食记录

每条记录包含：

- 食物名称
- 进食日期和时间，默认当前本地时间，可修改
- 分量描述，例如 `2 个`、`250 克`、`1 杯`
- 录入模式：手动填写或系统估算
- 最终卡路里数值

时间线按进食时间排序。用户可修改或删除记录；当天总量随之重新计算。每天按设备本地日期显示新的时间线，历史记录可以按日期查看。

### 卡路里估算

估算使用随应用分发的常见食物数据和关键词匹配，离线可用。估算结果必须标记为近似值，并允许用户修改。找不到可靠匹配时不生成虚假数字，改为要求手动填写。用户可把最终数值保存为「常吃食物」，以后快速复用。

## 钱包页面

### 创建预算周期

用户填写：

- 总金额
- 开始日期
- 周期类型：每天、每周、每月、自定义若干月、自定义若干年
- 建议储蓄比例，默认 20%，可调整为 0% 或其他有效比例

储蓄仅作为建议单独显示，不会锁定、转账或禁止用户消费。

### 预算算法

所有金额以整数「分」存储和计算。

```text
建议储蓄 = 总金额 × 储蓄比例
可用零花钱 = 总金额 − 建议储蓄
基础每日额度 = 可用零花钱 ÷ 周期实际天数
今日可用 = 基础每日额度 + 前一天结转
今日结转 = 今日可用 − 今日消费
```

除法产生的余数按分逐日分配到周期前面的日期，确保所有每日基础额度之和严格等于可用零花钱。

正余额和负余额都向次日结转。例如基础每日额度为 ¥100，今天消费 ¥130，则今天显示 `−¥30`，明天可用额度为 ¥70。如果负数大于次日基础额度，明天仍可显示负数并继续向后结转。

### 消费记录

每条记录包含：

- 消费名称
- 金额
- 消费日期和时间，默认当前本地时间，可修改
- 可选分类

修改或删除历史消费后，从该日期起重新计算所有后续每日额度与结转。页面显示本周期总额、建议储蓄、可用零花钱、今日可花、今日已花和消费时间线。

### 周期结束

周期结束时显示非阻断确认卡片，用户可以：

- 沿用相同总金额、周期和储蓄比例开始下一周期
- 重新输入总金额，相当于充值后开始下一周期
- 暂停，不创建下一周期

开始下一周期时，用户另外选择是否把上一周期最终正余额或负余额结转。未选择前不自动创建新周期。

周期长度按本地日历计算，月和年周期使用对应的自然日期规则，并正确处理不同月份天数、闰年和跨年。

## 数据与隐私

第一版使用 `localStorage` 保存轻量设置、饮食记录、常吃食物、预算周期和消费记录，与现有应用保持一致。不登录也能完整使用，离线状态下可新增、修改、删除和浏览历史。

第一版不把饮食和财务数据上传 Supabase。数据对象预留稳定 ID 和更新时间，未来若开启账号同步，必须另行确认隐私说明、数据库迁移和行级权限策略。

提供生活数据 JSON 导出和导入。导入前验证版本、字段类型、数值范围、ID 引用和日期；无效文件整体拒绝，避免部分写入。

## 输入与错误处理

- 卡路里必须是非负有限数值。
- 金额必须是非负数并规范化为整数分。
- 储蓄比例限制在 0% 到 100%。
- 自定义周期数量必须是正整数。
- 无效日期、结束早于开始或无法解析的导入数据均不保存。
- 本地存储失败时保留表单内容，并显示温和错误提示。

## 测试范围

- 饮食时间线排序、每日汇总、编辑删除与跨日历史
- 手动卡路里、可编辑估算、找不到匹配时回退手动输入
- 日、周、月、自定义月和自定义年周期
- 不同月份、闰年、跨年和本地日期边界
- 20% 默认储蓄、可调整比例和整数分余数分配
- 正余额、负余额、连续超支和历史消费修改后的重新计算
- 周期结束的沿用、充值、暂停和可选结转
- JSON 导入导出、无效数据整体拒绝和旧版数据兼容
- 中英双语、键盘操作、触摸目标和减少动态效果

## 不在本次范围内

- 医疗、营养或减重建议
- 在线食品数据库或图片识别
- 银行账户连接、自动扣款或真实资金锁定
- 饮食和财务数据的云端同步
- 社区分享、排行榜或公开展示个人数据
